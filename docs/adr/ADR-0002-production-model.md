# ADR-0002: PV制作モデルの導入（意味モデル → ProjectSpec コンパイル）

## 状態

Accepted

## 背景

初期の制作経路は、旧AEP（`legacy/pv-2dc99e1.aep`）のコンプ・レイヤー・ヌルを
`pv/generated/` へダンプ転記し、`pv/scenes/master.ts` がレイヤー名・旧
インデックス・`comp_05` への直接参照で配線を修復する構成だった。この方式では:

- レイヤー座標・親子・Layer Control 参照が旧AEPの内部配置に固定され、
  グリッドやセクションの設計変更がコードへ反映できない
- `pick(name)`・レイヤー番号の手動 remap・`any` による property tree 走査が
  master.ts に集中し、参照が名前・Z順・レイヤー追加で壊れる
- 「何を制御し、どの座標系で、何を追従させるか」がヌル名（`P-33` 等）から
  読み取れず、制作判断とAE内部表現が混在する

一方で、Restroの分解済み筆画のような再生成が難しいデータは素材として保持
する必要があり、素材と演出の境界を明示する必要がある。

## 決定

1. **意味モデルを正本とする**。Frame・Grid・Section・Anchor・Asset・Scene
   の制作モデルを TypeScript で定義し、人間が編集するのはこのモデルだけと
   する。AE のコンポ・レイヤー・ヌル・リグはモデルから生成する。
2. **コンパイルは一方向**。`compile(model) -> ProjectSpec` がモデルを既存の
   dump schema（`ProjectSpec`/`CompSpec`/`LayerSpec`）へ変換する。dump schema
   は AEランタイムへの出力契約であり、制作モデルとは別の責務として維持する。
   `pv/runtime/aeRuntime.ts` は変更しない。
3. **参照は安定ID、解決は生成時**。セクション・アンカー・素材・コンポへの
   参照はすべて文字列IDで行い、AEレイヤー番号・`sourceCompIndex`・レイヤー名・
   Z順への変換はコンパイル時にのみ行う。未知ID・重複ID・未解決参照は
   コンパイル時エラーとし、生成物に壊れた参照を残さない。
4. **グリッドは明示的な設計モデル**。画面寸法・余白・列・行・間隔・領域を
   GridSpec として定義し、レイヤー座標は旧AEPから複製せずレイアウトモデル
   から計算する。既存配置のうち維持すべき部分と改善すべき部分は
   `docs/SPEC.md` と実測に基づき区別し、過去の数値を無条件に正本としない。
5. **セクションは意味単位**。`Heading`/`Description`/`Icon`/`Main` のような
   領域をコンポ名ではなく role を持つ Section として扱い、内容・配置・
   表示期間・アニメーション・依存を持てるようにする。シーンごとに必要な
   セクションを組み合わせ、全シーンへの同一固定配置を強制しない。
   `master` はシーンの時間配置と合成のみを担当する。
6. **アンカーは制御意図を持つ**。ヌルは「何を制御し、どの座標系で、何を
   追従させるか」を宣言する Anchor としてモデル化し、親子・追従・
   Layer Control 参照はIDで結ぶ。生成AEPでは役割が分かる名前と階層にする。
7. **素材と演出を分離する**。Restroの分解済み筆画など再生成が難しいデータは
   素材AEPとして保持し、Asset ID 経由で参照する。グリッド・セクション・
   トラッキング・タイムライン・アニメーションは TypeScript 正本とする。
   旧 `master` 全体や完成シーンをそのまま参照する方式は移行中の暫定措置と
   し、最終的に `pv/generated/` の転記依存を解消する（#10）。
8. **完了条件**。TypeScript でグリッド・セクション・アンカー・素材・演出を
   変更すれば、それらの関係を保った AEP が再生成されること。旧AEPの
   レイヤー名や番号を人間が調べて複製・修復する必要がないこと。

## 影響

- 新規: `pv/production/`（制作モデルとコンパイラ）、`pv/spec/`（旧
  `pv/model/types.ts` のdump schema。AE出力契約として改名・移動）
- 変更: `pv/scenes/master.ts` は #8 で `pv/scenes/production.ts`（モデル記述、
  レガシーダンプからの移行shimを内包）へ置き換え、`pv/generated/` は
  #9・#10 で段階的に縮小・撤去
- 契約テスト: グリッド変更→配置反映、アンカー変更→追従伝播、参照の
  rename/追加耐性を `bun test` で検証する
- `docs/SPEC.md` のシーン要件（A1〜E）は変更しない。制作モデルは SPEC を
  実装するための構造であり、演出仕様の正本は引き続き SPEC.md とする

## 却下した案

- **現行方式の延長（転記+修復の継続）**: 旧AEP内部配置への依存が残り、
  シーン追加のたびに手作業の整理が必要になるため却下
- **AE側でコンポを組みMCPで逐次編集**: AGENTS.md の制作主経路に反し、
  再現性・検証性が下がるため却下（AGENTS.md 境界どおり）
- **モデルからAE DOMを直接操作する別ランタイム**: 既存の検証済み
  ProjectSpec→JSX→AE 経路を捨てるコストに見合わないため却下。
  モデル層を追加し、出力契約は維持する
