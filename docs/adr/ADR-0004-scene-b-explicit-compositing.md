# ADR-0004: Bシーン合成構造の明示的TypeScript生成への転換

## 状態

Accepted

## 背景

Issue #19 Step 3 で、旧 master の B 区間（4.25–7.92s）を `pv/scenes/scene-b.ts`
のセマンティックセクションとして再構成した。初期実装は旧 AEP の stored
track matte 値（`trackMatteType` 5012/5013）をそのまま emit する方式だったが、
f120/f160/f185 の実機比較で元 master との間に再現できない差異が残った。

v10 の局所対照実験（`verification/sceneb/v10-matte-isolation/`）で以下が
確定した。

- 旧 master の stored マットはレイヤーごとに実効状態が不整合
  （stale なバインドと live なバインドが混在）しており、5012/5013 を
  再 emit するだけでは同じ実効状態を再現できない。
- gen 側で全マットを 5012 にした場合（gen-D）は leg の全マット無効版
  （leg-nomatte）とほぼ一致し、非マット構造の再現性は確認済み。
- 管理された AE 実験で、ゼロアルファのヌルを ALPHA マット源にすると
  対象レイヤーが完全に消去されることを実証。B シーンの `P-71` は
  まさにこのゼロアルファ・トラッカーヌルであり、これをマット源にした
  Lens magnifier の 5013 バインドは拡大内容を消去する。
- ルーペ領域の描画はマット有無の各バリアントでほぼ同一であり、旧来の
  「P-71 マットがルーペ窓として機能している」という解釈は成立しない。

## 決定

旧 AEP の stale トラックマット再現を打ち切り、B シーンの合成構造を
TypeScript から明示的に生成する方式へ変更する。

1. **STEP drafts / outline は非マット（5012）で描画する**。
   工程フレーム（`STEP * border` / `STEP * card`）は情報表示のための
   可視レイヤーとして維持し、マット源としては使わない。筆画の表示範囲は
   素材 comp 内部の構成に委ね、必要になれば独立した明示的マスクを
   個別に生成する（現時点では素材 comp が自己完結しているため付与しない）。
2. **Lens magnifier の表示窓はレイヤー自身の明示的マスクとする**。
   旧 `lens matte` シェイプ（master 座標 (660,810)、半径約210、
   ~4.97s にポップインする減衰ばね付き円）を解析し、同じ窓を
   `ADBE Mask Parade` として TypeScript で生成する。拡大内容が窓外へ
   漏れないことが構造的に保証される。`LENS frame` リングのクローンは
   窓の輪郭として残す。
3. **P-71 を撤去する**。ゼロアルファ・マット源として無意味であり、
   式参照も存在しないことをダンプで確認済み。
4. **工程ラベルは累積・順次出現とする**。SPEC §10.3 の「タブ／ラベルを
   工程進行に同期させて順次出現させる」に基づき、Lens comp 内部の
   ステージ窓（輪郭解析 4.25–5.00 / 延長 5.00–5.63 / 隠れ頂点推定
   5.63–6.63 / 筆画再構成 6.63–7.92）に合わせて各ラベルの inPoint を
   設定する。一度出現したラベルは残る（履歴保持）。
5. **トラッカーリグと素材 comp は維持する**。Linked Quad 系の
   corner tracking、`comp("master")` 参照、実 Restro 筆画素材 comp の
   ビット一致は引き続き有効であり、今回の変更はマット・クリッピング・
   工程状態の責務分離に限定する。

## 影響

- `pv/scenes/scene-b.ts`: `P-71` / `lens matte` を clone 対象から除去、
  drafts/outline/STEP1 outline の 5013 を撤去、border/card クローンの
  `isTrackMatte` を明示的にクリア、Lens magnifier に `lensWindowMasks()`
  による明示マスクを付与、タブラベルの inPoint をステージ開始時刻へ。
- `tests/scene-b.test.ts`: マット非存在・窓マスク形状・ラベル逐次出現・
  border/card の可視性を不変条件として固定。
- `docs/SPEC.md` §5・§10.3 の要求（同一の「筆」・4工程の累積・意味の
  ある色状態・ルーペの意味性・ラベル可読性）は変更しない。本 ADR は
  その実現方法を「旧マット構造の模倣」から「明示的な制作モデル」へ
  置き換える判断を記録する。
- 実機検証（f120/f160/f185 の描画確認）は Issue #21 の AE 不安定問題に
  より未完了の場合がある。静的検証（typecheck / bun test / jsx:check /
  ae-test fake host）は本決定時点で全てグリーン。

## 却下した案

- **stored 5012/5013 の再 emit 継続**: v10 で実効状態の不整合と
  ゼロアルファ・マット源による消去が実証され、再現コストに見合わない。
- **P-71 をマット源として残す**: 実効アルファがゼロで対象を消去する
  ことが実証済み。参照も存在しない。
- **border をマット源とする明示的トラックマットの維持**: border の
  ストローク alpha でクリップする方式は旧来の「疎な描画」を生む
  挙動であり、工程の累積表現としては素材 comp 内部の構成に委ねる
  方が SPEC の意図に合う。
