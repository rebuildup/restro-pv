# PV アートディレクション v13 — 20秒全体を一つの作品として設計する

本書は v12 全編批評 (MiniMax-M3 による11フレーム時系列評価) と原本 pv-review.mp4 の分析に基づく、v13 の制作正本。個別シーンのPASS稼ぎではなく、**静止画の代表構図が映像デザインとして成立すること**を先に確定し、その上で時間方向の展開を作る。モーションで静止時の設計不良をごまかさない。

## 原本から学ぶ設計上の強み (分析済み)

- 左カラムは「情報の机」: 上部にブランドロックアップ、下にシーン別コピー。右ステージが常に主役。
- A: 右側に巨大な漢字ヒーローがフレーム端でクロップされ、左→右へ抜ける構図が分解の意味を持つ。
- B: 番号付き工程 (01–04) と拡大レンズで「実処理の中間情報」を見せる技術図解。
- C: 白いアートボードに仕上がった筆文字を単体で大きく見せるギャラリー構図。技術色からの反転が「作品化」を意味する。
- D: デスクトップ全体ではなく、操作に必要な範囲だけを右端でクロップしたキュレート画。赤いコントロールポイントが注釈の役割を果たす。
- E: 静かな終了カードを最後まで保持する。
- リズム: 巨大タイポ(疎) → 技術図解(密) → 作品(清) → 実操作(密) → 終了(疎)。

## v12 の致命的欠陥 (M3 全編批評・重要度順)

1. **核心的実演が読めない** — 画面キャプチャが小さく散らかり、決定的な before/after がない。プラグインの価値が伝わらない。
2. **終了カードが未完成** — ブランド重複、URLが弱い、CTAがヒーローになっていない。
3. **内部成果物の露出** — 「D—操作」等のシーンラベル、スクリプト実行ログ窓、注釈用グレー帯がそのまま残り、制作途中感を与える。
4. **本文が過密・過小** — 細かいグレー文字とグリッドの競合で可読性が低い。
5. **ペイオフの回収がない** — Cで一度だけ小さく出る多色筆画ヒーローが、その後二度と大きく戻らない。
6. **左レールが静的で支配的** — 同じ位置に長時間留まり、情報密度が上がらない。
7. **パネル様式の不統一** — グレー角カード・白額縁・生AEダークUIが無秩序に混在。
8. **cut の羅列で橋がない** — ストローク→UI領域、グリッド→ステージ等の視覚的match cutがない。
9. **色の意味が場面ごとに変わる** — 赤=ブランド/解析中/選択/ハンドルが説明なく混在。

## v13 グローバル設計系

### レイアウト (1080×1080)

- 左カラム x≈40–460: ブランドロックアップ (Aeバッジ+Restro+筆画復元) を上部に固定。ロックアップは v12 より一段小さくし、シーンコピーは各シーン1–2行・18px以上・高コントラスト。コピーが左を埋め尽くさない。
- 右ステージ x≈480–1040: 全ヒーロー要素。ステージ内の要素は「ビューポート」系に統一 — 白または薄グレーの一枚の面 + 細い黒またはグレーの縁で切り抜く。角丸カード・影・Web風装飾は禁止。
- 背景グリッド: 線を薄く (主張しない)、パララックスまたは緩やかなズームで奥行きを出す。静止した壁紙にしない。文字情報が密な場面ではさらに減衰させる。

### タイポグラフィ

- 書体は現行の系を維持。本文最小 18px 相当、行間を確保。エディトリアルな大見出し (シーンの主張1行) と小さなラベルの2階層。3階層以上の同居を避ける。
- 折返し・行末・禁則を機械的に確認。キャプションは必ず完結文で、comp端で切れない (masterPatch の fit pass を維持)。

### 色の意味 (全編で一貫・凡例不要に設計)

- 赤 = 現在の工程・ブランドアクセント (Restroの赤)
- 黄/アンバー = 選択・注目領域
- 緑 = アクティブなポイント/ノード
- 多色筆画 = 分解済み成果物 (作品の完成形)
- グレー = ゴースト/休眠状態
- Aで一度だけ暗に確立し、B–Eで同じ意味を再利用する。意味のない色変化をしない。

### シーン別キーフレーム構図 (先にこれを成立させる)

**A (0–約3.6s) — 問い**
巨大な黒い漢字ヒーローが右側でフレーム端を bleed し、左→右へ抜ける。左カラムにロックアップ+「筆画復元」+フック1行。ヒーロー自体が分解され、最後は分離した筆画群として収まる。Aの最終フレーム=全編の問いの形。

**B (約3.6–7.4s) — 証明 (技術)**
右ステージ中央にアウトライン付きビューポート、内部に工程中のグリフ。番号付き工程が順に点灯 (赤=現工程)。拡大レンズ/窓で実際の中間情報 (スキャンライン・頂点・ソルバ点) を1つだけ見せる。情報は「このツールが実際に何を計算しているか」に絞る。工程帯は番号+短い名詞のみ、本文を詰め込まない。

**C (約7.4–11.7s) — 作品**
白いアートボードに仕上がった作品を1点ずつ大きく (各1.2s以上保持)。技術色からの反転=作品化。作品は「完成したデザイン」として読めること (抽象グリフの羅列不可)。キャプションは作品名レベルの最小限。3点の時間配分を均等に近づけ、駆け足にしない。

**D (約11.7–15.4s) — 実演 (証拠)**
決定的な before→after を1つの大きなビューポートで見せる: 入力テキスト → 分解・再処理 → 筆画シェイプ結果。実操作録画の該当区間をキュレートしてクロップ・ズーム。ダイアログを主役にしない。小窓のモザイク・内部ラベル露出は禁止。録画素材に決定的区間がなければ AE 自動化経路 (docs/ae-pipeline.md) で再録画を検討し、不可能なら何が欠けているかを証跡に記録する (黙って省略しない)。

**E (15.4–20s) — 回収と販売**
2ビート構成:
1. **ペイオフ回収** (~15.4–17s): Cの多色筆画ヒーローが全画面スケールで再出現し、Aの黒い漢字ヒーローへ収束する (問い→答えの円環)。
2. **終了カード** (~17–20s): 正規ロゴ素材 (汎用フォントの製品名ワードマークではない) + 製品名は1回だけ + BOOTH + URL を明確なCTAとして保持。Web風カード・影・角丸・重複表記なし。最後まで静止保持。

### 遷移

基本はハードカット。連続性が意味を持つ境界のみmatch cut (筆画のエッジ→UIのバウンディングボックス、グリッドの押し込み→ステージへの遷移)。「滑らかさ」自体を目的にしない (transition-design skill準拠)。

### 評価

各シーン担当は `VISION_MODEL=MiniMax-M3` (既定化済み) で自シーンのキーフレーム系列を**作品として**批評させ、基準PASSだけで完了としない。全編評価は統合後に別途実施する。
