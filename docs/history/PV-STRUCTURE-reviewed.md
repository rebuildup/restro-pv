# Restro PV 構成・演出仕様（Fable案レビュー修正版）

> 状態：**実装用の設計基準／詳細座標・素材の一部は要実機照合**。Fable原案を再検討した版。ユーザーが確定した演出意図と、Fableが提案した具体値を区別する。見た目の不成立を避けるため、未検証の数値・レイヤー名・アルゴリズム説明を無条件に実装しない。
>
> 対象：`rebuildup/Ae_Restro` の `promo`、制作基準 `95a235f`、`promotion/pv.aep` の `master`。`promo` のHEADは作業開始時に再確認すること。`pv.aep` は `21a6b78` の復元版で、既存 `promotion/beats/` の43枚と実機でpixel一致を確認済み。**一致は再現性の証拠であり完成判定ではない。**

## 1. 何を伝える映像か — 確定した目的

「Restro」（Restore Stroke）は、重なって一体に見えるベクター輪郭から筆画ごとの形状を**推定して再構成**し、After Effectsで独立したシェイプとして編集できるようにする製品。「文字を切る」「輪郭を単に裁断する」「一文字ずつ分ける」のではない。交差で隠れていた形まで推定されるため、元の輪郭を見ているだけでは分からない独立形状が得られることを**実際のRestro出力**で見せる。

映像の情報の流れ：**導入 → 普通の分解と違うという違和感 → 同一文字上で処理原理を順に見せる → 復元筆画による作品例 → 実際のAE操作 → 締め・販売情報**。主目的は関心・理解・購買につなぐこと。単なる機能一覧、Web UI風カードの羅列、抽象図形だけの映像にしない。処理は推定であり、元の筆順・意図・形状の完全復元を断言しない。

## 2. 保護する演出と再設計する部分

### 変更禁止の本質

- **B（beat 10〜17）**：**大きな同一の「筆」一文字**を固定し、その輪郭上に解析→延長→隠れた部分の推定→筆画への再構成という処理結果を、フィルターのように**時間とともに重ねる**。既存のSTEP・帯状タブ・拡大レンズの発想を継承する。**2×2の工程カード／4文字の比較図に変更しない。**
- A2（beat 5〜8）：Restro出力の独立筆画を大きく見せ、通常の裁断では得られない交差の奥の連続形状を見せる。単なるパーツ飛散では不可。
- C：複数の**完成した作品**を、右側の**縦方向にスクロールする映像ストリップ**で見せる。
- D：**複数の実AE操作録画**を、それぞれ独立したウィンドウで**非同期に登場・再生**。Cの縦スクロールを使い回さない。
- 背景のグリッド、左のブランド／説明、右の映像主役という構成、白黒を主とするトーン、Restroの赤は継承する。ただし、意図的な大きなはみ出しと、意図しない文字・映像の衝突を区別する。

### 固定しないもの（Fable案としての提案）

細かな座標、表示倍率、ラベルのフォントサイズ、各作例の色、操作窓の数とサイズ、Eの3タイル／円形再集合、演出のイージング、左右ゾーンの厳密な境界は**初期案**。既存AEPを読み取り、視認性・意味・時間的連続性を満たすようエージェントが調整できる。全要素を「±8px」「±2フレーム」に限定しない。シーンの役割を変える場合のみ新たな設計判断として記録する。

## 3. 尺・時間の扱い

- `master`：1080×1080、24fps、20秒＝**480フレーム**。フレーム番号は0〜479。画面時刻は `f / 24` 秒。
- BPM 128、1拍＝0.46875秒＝11.25フレーム。第n拍頭の理論位置は `(n−1)×11.25` フレーム。静止画像は整数フレームで確認し、音楽の拍とフレームの丸め差を考慮する。
- 区間は**半開区間**で記す。A1 `[0,45)`、A2 `[45,90)`、A3 `[90,101)`、B `[101,191)`、C `[191,281)`、D `[281,371)`、E `[371,480)`。場面転換用の前後数フレームのオーバーラップは許容するが、どの要素が前面か、どこで旧場面が消えるかを明示する。

## 4. 画面・文字のデザイン

### ゾーン設計（候補）

- 左：ブランド表示とシーンの説明。おおむね `x=0〜460`。`Ae` バッジ、Restroロゴ、「筆画復元」を原則継承。説明は左中央下、現行の `description` の実測範囲を確認する。
- 右：主役となる文字／工程／作品／録画。おおむね `x=480〜1080`。`x=460〜480` は文字・録画の安全距離の**目安**。
- 意図的に画面外へはみ出す巨大文字は許容する。**意味のある文・工程ラベル・操作対象が隠れる重なりは不可**。安全距離は実画面で判断する。
- グリッドは表示面と位置決めの共通言語。装飾枠を増やすための道具ではない。グリッドに沿った大胆なスケール差・余白・対比を使う。
- 画面全体での情報の優先順位を決める：主役の映像／左の一文／補足。不要な英語注釈は削るが、ブランド表示の `AFTER EFFECTS PLUGIN` や実AE UI、正規のURLまで禁じない。
- **主コピー36px、補足24px、タブ22pxなどの指定は仮値**。実レンダーでサイズ・字幅・可読性を検証する。下限値を機械的に適用してラベルがはみ出すなら、文字量・表示方法・配置を優先して修正する。
- コピー入れ替えはモーションを伴ってよいが、文字同士が同時に読めなくなる残像・衝突を起こさない。重なりが実際に起きるかを中間フレームで確認する。

### 左コピー案（表現の意味を保ち、全文確定は実画面で）

| 区間 | 主文 | 備考 |
|---|---|---|
| A1〜A2 | 「文字の輪郭から、／筆画ごとのシェイプへ。」→「こんな文字分解、／見たことがありますか？」 | **現行beat2〜4ですでに後者が表示されている**。A1を既存どおり残すなら質問をbeat5から初めて出すよう強制しない。切替時刻は実際のAEPと演出に合わせる |
| B | 「つながった輪郭から、／一画ずつの形を復元する」 | 既存の方向性を継承。補助の「交差の奥の形を推定して、／組み直す。」は候補。重複する小文は無効化前に責任を確認 |
| C | 「分かれた筆画で、／もっと自由な動き・表現」 | 語感は再推敲可。作品が主役で文章を増やさない |
| D | 「After Effectsで、／そのまま動かせる。」 | 「筆画ごとに編集できる」事実と操作映像に合わせる。操作していない機能の宣伝をしない |
| E | 「輪郭から筆画へ。／筆画から表現へ。」 | **候補**。最終画面はRestro名、筆画復元、BOOTHで販売中、取得先が一目で分かることを優先 |

現在の途中で切れた日本語・英語や説明の多重表示は修正対象。しかし**テキストレイヤーを番号指定でまとめて削除せず、表示時刻と依存関係を見て**無効化・整理する。

## 5. シーン別の表現と受入条件

### A1 `[0,45)`：既存の導入を保護

- 現状の巨大な「解」と、その独立筆画によるズレ・復帰、左ブランドを継承する。最初の4拍は**既存PNGと一致することを原則**とする。
- Fable原案は「A1変更しない」としながら、A2用に既存の子レイヤーのアウト点をf36→f101まで延ばしており、A1のf36〜44にも影響し得る。**A1のレイヤーを直接延長して改変しない。** A2には必要な範囲を複製して別プリコンポに隔離する。
- さらにFable案の「質問コピーはf47から」は現行beat2〜4の画像と矛盾する。A1のコピーを勝手に差し替えない。

### A2 `[45,90)`：普通の裁断と違う「復元された一画」を見せる

- 主役候補は巨大な「解」の右部（牛部分）にある交差した縦画・横画。Fable案は `STROKE_016_runs4`（縦）、`STROKE_015_runs4` と `STROKE_017_runs4`（横）を選んでいる。**実際のAEPで対応・形状・出自・親階層を確認**してから採用する。
- 見せたいのは「交差で見えなかった部分まで連続した一本の縦画として成立している」こと。**横画が途切れずに残るだけではRestro固有の証明にならない。** 元の文字の輪郭／交差位置のゴーストと、引き離した縦画の隠れていた部分を対応付ける。
- 演出候補：f45〜55で文字の交差周辺を大きく見せる → f56〜66で縦画を分離 → f67〜78で横画を離し、推定された交差内部をアクセント色で強調 → f79〜89で比較状態を保持し、Bへ接続。数値（130%、+245px等）は**画面結果を見て調整**。
- パスを任意に裁断して作り直さない。色のマット・ハイライトは復元された形のどの部分を示すか検証する。**Fable案の複製を別筆画の子にする手順を無検証で実行しない**。親子・座標・マットの追随をテストしてから決める。
- `kai-zoom`・`bunkai`等の既存レイヤーは除去前に表示区間と前後の接続を調査。無差別に消さない。
- **受入**：拡大された筆画が独立した一つの形として認識でき、どこが隠れていた部分か一目で追える。左の問いと映像が対応している。

### A3 `[90,101)`：原理説明への橋渡し

- 「解」から「筆」への視線の移行が主目的。上方向のスクロールは候補であり、**次のBの大文字を予告する転換**としてつなげる。
- Fable案の16本を個別に上へ1080px飛ばす方法は、直前の復元表現を雑な飛散に見せる可能性がある。全体・グループ移動を優先し、必要な差のみ時間差を付ける。
- CやDまで全て同じ上方向転換にすることは固定しない。特にDはCとは異なるマルチウィンドウ演出。

### B `[101,191)`：原理、**同じ巨大な「筆」一文字**

- この区間の演出構造は**絶対保護**。現在のSTEP系コンポ、帯状の段階表示、ルーペを読み、別々の文字・独立した4カードに作り直さない。
- ひとつの文字を基準の位置と輪郭で保ったまま、段階が進むと観測・強調される情報が積み上がる。**「累積」は不透明な塗りを全て重ね続ける意味ではない。** 工程ラベルの履歴は保持し、幾何・補助線は必要に応じて色・透過・表示優先度を変え、説明対象が隠れないようにする。
- ステップの候補：01 輪郭を解析（f101〜123）、02 輪郭線を延長（f124〜145）、03 隠れた部分・頂点を推定（f146〜168）、04 筆画として再構成（f169〜190）。タブ／帯は順に追加。既存の赤・緑・青・黄は役割に応じて使い、文字は読める濃淡・幅を確保する。
- Fable案のカード `x496〜1068`、文字の74%縮小、ルーペ中心(640,850)、ルーペ倍率300%、交差8箇所、`FUDE S01〜S13`という具体値・レイヤー名は**実機照合前の候補**。既存の文字が大きく見えること、対象位置とレンズの関係が明瞭なことを優先。文字を収めるためだけに小さくしない。ルーペがタブ・本文・焦点を覆わない。
- **重要な技術的注意**：Fable案の「筆画の複製を相手のアルファマットで切ると内部延長線や推定頂点が得られる」は、実際の推定処理を再現する方法としては証明されていない。マットの端は必ずしも「隠れた頂点」ではない。**実際の出力形状と処理契約を照合**し、観察可能な幾何だけを可視化する。内部アルゴリズムにない処理を実動作として断言しない。
- ステップ04では、同一文字上で各筆画が独立していることを少しの変位・配色・選択状態等で伝える。「元の文字からバラバラの小文字に切替」では不可。
- **受入**：段階の全時間を通して対象は同一の「筆」。各段階で何が増えたか分かり、ルーペは意味のある箇所を示す。工程ラベルと説明文が読める。既存のBの発想が破壊されていない。

### C `[191,281)`：作品例の**縦スクロール**

- 右側の**ひとつの縦長の窓**の内側に複数の「作品」を縦に並べ、上下に送る。各作品内にも筆画アニメーションがある。**主役はスクロール自体ではなく、認識できる完成作品。**
- 作品の候補は3つ：A「筆画が集まって文字になる」、B「完成した文字に筆画ごとの時間差の波」、C「文字の筆画を使って別の構図を作る」。どれも**実Restro出力**で作り、色・運動・完成像の差が分かるようにする。
- Fable案の幾何（`PV showreel` 1080×3240→600×1800、窓x480〜1080、各作例600角）は参考になる。コンポの**アンカーが中央で空間的にA/B/Cを上・中・下に積む**なら、表示の中心に必要なYはA=1140、B=540、C=−60（X=780）で整合する。ただし**最初の作例の上／最後の作例の下には隣接作品が存在しない**。上下240pxとも他作品がのぞくという説明は誤り。空きを意図的な余白として設計するか、ストリップの始点／終点演出を加える。
- **重大なタイミング修正**：Fable案はCの完成形をf247〜259で見せる一方、Cが窓の中央に来るのはf255以降としており、文字の完成形が中央で数フレームしか見えない。Cを含む全作品で、**実際に窓へ入った時刻**を基準に「完成像の認識→動き→収束」を割り付ける。特にCは完成文字と放射状の最終像の両方を見せたいなら、その保持時間を確保する。尺が足りなければ3作品の密度か運動の種類を調整し、フレーム数の数字を守るために見えない時間へ演出を押し込まない。
- `PV showreel`の大きさ、workコンポの空間上の位置、レイヤーの`startTime`/`inPoint`/`outPoint`/`stretch`/タイムリマップ、マット、合成順を**実画面で検証**。同じ時刻に動く3つのworkが意図した画面で出るとは限らない。
- **転換注意**：Fable案はCをf288まで画面上に残す一方、Dをf281から右全面に表示するため、2場面が衝突する。Cはf281のD開始で隠れるように終了させるか、明示的なマスク／前後関係を設計する。全幅の不透明レイヤーをDの上に残さない。
- **受入**：少なくとも複数の作品について、移動中の断片ではなく全体の形・意図した動きが認識できる。スクロールの前後とコンポ内動作が同期する。不要な空白やはみ出し、左本文の侵食がない。

### D `[281,371)`：実AE操作の**非同期マルチウィンドウ**

- Cとは異なり、独立した短い録画窓を複数配置し、それぞれが少しずつ違う時刻に始まって終わる。ランダムに見えるが配置はグリッド上で構成する。
- Fable案の**主画面1＋補助3**は有力な配置案。候補矩形：W1 `x480〜1080,y96〜546`、W2 `x480〜772,y562〜984`、W3 `x788〜1080,y562〜765`、W4 `x788〜1080,y781〜984`。主画面は操作の因果関係が分かる大きさ、補助画面はレイヤー・筆画編集・プレビューの要点をクロップする。4等分はしない。
- W1：実際にDecomposeを実行し、分解前→分解後が同一録画内で分かる。W2：生成された独立シェイプ。W3：筆画ごとの移動・回転。W4：キーフレームを使った結果。**収録素材が証明できる操作だけ**を扱う。架空のAE UI・偽の機能操作を作らない。
- Fable案は窓の見やすさをUI倍率や14pxで数値固定しているが、実際の録画解像度と表示縮小率が支配的。**画面に最終配置したフレームを見て、押したボタン、結果、レイヤーなど必要部分を判読できること**を合格条件とする。W2/W3/W4が常時動作することは要件ではない（操作結果の静止も意味がある）。
- 過去の実録画はバックアップブランチにある。新たに4本録ることを無条件に決定せず、**既存素材を画質・内容で確認し、足りない部分だけ収録**する。UIの解像感を損なう無理な拡大をしない。
- **転換注意**：W1の4:3の映像を、Eの正方形タイルへ無変形縮小すると歪む。必要ならマスクでクロップし、被写体が見えることを確認する。Eへの接続は候補であり、成立しなければ別の転換に変更してよい。
- **受入**：窓はグリッドと情報優先度に沿い、左の文字を壊さない。実操作の前後と結果が追える。Cのスクロールとの演出差が明確。

### E `[371,480)`：締め — **仮案を確定仕様にしない**

- この区間はユーザーが**まだ構想を確定していない**。Fableの「3枚の総括タイル→円形に16筆画→再集合→商品カード」は**候補案**。それが視覚的に成立し、20秒の締めとして強いかを評価したうえで決める。
- 少なくとも、Bの原理、Cの表現、Dの操作を一瞬で回収してからRestroの名前と販売情報へ結び付けるという方向性を優先。タイルや早送りモンタージュは使ってよいが、単なるダイジェストの重複にならないようにする。
- 冒頭の「解」に帰着する案は有力。ただしFable案にある `STROKE_016_runs6` とA2候補の `STROKE_016_runs4` が**同じ形状・出自であるとは未検証**。番号だけで同一筆画と主張しない。どの筆画を赤くするかも映像の意味から決める。
- 最後は必要情報の**認識可能な保持**を確保する。候補文「輪郭から筆画へ。／筆画から表現へ。」、商品名「Restro」、筆画復元、BOOTHで販売中、正しい商品URL `https://361do.booth.pm/items/9029239`。ブランドが常設だからといって、最終画面の**主役としてRestro名が認識できなくなる**構成は避ける。
- URLの長さ・書体によっては、Fable案の46pxで指定横幅に入らない可能性がある。**実測するまでサイズを固定しない**。読めないURLを大きく置くより、短縮表記・文字組み・画面上の情報整理を検討する。QRは必須ではない。
- 最終静止は有効だが、Eの全区間に無意味な運動を敷き詰めない。BGMの実際の終端・アクセントを聞いて切替とフェードを決める。
- **受入**：それまでの表現から自然に締まり、商品名・何ができるか・入手先が読み取れる。最後のフレームまでUI、文字、主役が衝突しない。

## 6. Fable案から持ち込まない確定事項

1. **「A1変更しない」とA1の表示コピー・子レイヤーを変更する矛盾**。A1の既存フレームを保護したうえでA2用に複製する。
2. **Bの74%縮小と硬直した座標**。文字の迫力を優先し、同一文字と処理レイヤーの関係を保ちながら収まりを検討する。
3. **8交差・延長線・頂点をマットの端から自動生成できるという未検証の技術断言**。実Restroの観測結果として説明可能なものだけを使う。
4. **Cの「上下の隣接作例が常に見える」という幾何上の誤り、完成形の表示時間とスクロール位置の矛盾、Dとの表示期間衝突**。実際の投影・時間位置から直す。
5. **Dの4本新録・UI倍率・全窓常時動作という過度な固定**。既存素材を検証し、必要な収録だけ補う。
6. **Eの具体演出・タイル数・円形再集合をユーザー承認済みの決定とすること**。構想案として視覚的に比較・選定する。
7. **`master` レイヤー数263という断言**。現行manifestは260レイヤー。実機で再取得し、対象SHAと数え方を併記する。
8. **「ラベル22px」「24px未満の文字禁止」「小さい英語は全部禁止」の矛盾**。残すブランド・実画面UI・URLと無意味な注釈を区別する。
9. **「緩衝帯に何も置かない」「すべての移動は上」「リニアは不許可」「ブラー等は一律禁止」**。意図・読める構図・テンポを基準に調整する。
10. **未確認箇所の人間承認待ち**。設計・技術上の普通の判断は目的と証拠から自律決定する。ただし元のシーンBの意味変更、外部公開、リリース統合など別の権限境界は守る。

## 7. 制作素材の扱い

- 現行 `pv.aep`、`beats/`、BGMをベースラインとする。Git上のPNGは参照・レビュー用。AEPを保存したらビルド／レンダー結果が対応するように版を記録し、古い画像を「新AEPの証拠」に使わない。
- グリッド、`Logo`、`description`、既存のSTEPコンポ、ルーペ、Restro生成の筆画等は必ずAEで参照関係を調べてから使う。コンポ・レイヤー名が同じでも複数インスタンスを同一視しない。
- `PV work A/B/C`、`PV showreel`、`PV matte C`は未完成のscaffold。過去のC修復コードは退避ブランチを**原因の参考**として参照可だが、破壊的なシーン再設計を再導入しない。
- `promo-backup-redesign-20261119`には実AE録画・診断コードがある。採用は**素材・技術単位で評価**し、画面構成やAEPを丸ごとチェリーピックしない。
- ブランチの旧状態、作業前コピー、未追跡のAEP/AVI/Auto-Saveを保存し、無断削除しない。外部素材は出典・許可を確認する。

## 8. 受入条件と確認方法

**実装したこと**と**画面で成立していること**を必ず分けて報告する。

### シーンに共通

- ひとつのフレームで何を見るべきか分かり、重要な本文・図・操作の因果関係が読める。
- 意図しないクリッピング、マットの欠損、関係ないレイヤーの上書き、文字の重複、左の説明と右主役の干渉がない。
- 固有の意味が通じる。A2は復元、Bは同一文字の連続処理、Cは完成作品、Dは実操作、Eは商品認知。
- 実際のRestro出力を使っていること、再構成を単なる切断として誤認させないこと。
- 代表静止画に加えて**中間フレーム、切替直前直後、短い連続動画**で検査する。画素差分やレイヤー数だけで合格にしない。

### 場面別の重要検査

| 区間 | 見る点 | 確認タイミング（例） |
|---|---|---|
| A1 | 現行の4拍画像を保護 | f0, f11, f23, f34, f44 |
| A2 | 縦画が一本のまま隠れた形を持ち、問いと連動 | f50, f62, f76, f86 |
| B | 同じ巨大な「筆」、工程とタブの累積、ルーペの対象一致 | f110, f135, f158, f178、各間の数フレーム |
| C | 作品そのものが見え、スクロール位置と局所動作が一致 | 各作品の中央表示前・中・後、C→D境界 |
| D | 操作前→実行→結果が追える、必要なUIが読める | W1の押下前後、全窓同時表示、D→E境界 |
| E | 締めの情報階層、読み時間、文字とURLの収まり | まとめ前、商品表示直後、最終2拍 |

### 検証の段階

1. **着手前**：現行AEP、参照素材、対象レイヤー、フレームの読み取り専用検査。`promo` の基点を保存。
2. **デザイン構図**：シーンごとの代表フレームを制作・取得して視覚確認。最初に画面を成立させる。
3. **局所アニメーション**：各シーンの開始・中間・終了・境界を短い映像で確認。動きがあっても意味がなければ不合格。
4. **最終候補**：masterの0〜479全フレーム、20秒音声付き動画、拍画像43枚を生成し、視覚・読解・音楽同期・素材出自を総合確認。`pv.aep`と生成物が同一候補SHA／制作状態に対応する証拠を残す。
