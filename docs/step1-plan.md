## 試作（実 Restro 筆画データのみ・ダミー図形なし）

Baseline コンポの FUDE S01–S13（Restro Decompose 実出力、13 筆画）を
`compStrokes`/`StrokeField` で取得し、筆画ごとの独立 transform のみで
演出。1080×1080 / 24fps / 4 秒 / BGM 先頭付き。

- `verification/proto/hook-a.mp4` — A案「カスケード組立→完成→ドリフト」
- `verification/proto/hook-b.mp4` — B案「スラムイン→爆発分解→保持→再結集」
  （第三者批評を受け velocity 分散・impact punch を追加した v2）

## 第三者批評と方向決定

MiniMax-M3 による静止画・モーション連続フレーム批評（計2ラウンド）。
観察事実と批評の区別は PR #27 のコメントに記録。

- B案をフックに採用。完成形の一瞬提示→破壊→再結集の「対立と回収」が
  4 秒に収まり、音楽 PV の impact と接続しやすい。
- A案の「部品が集まって完成する」構成は破棄せず、種明かし幕
  （分解→復元の因果を見せる区間）の素材として再利用価値あり。
- 共通の改善指摘: 分解中の筆画同士の交差・奥行きを設計する、
  再結集の終端を完全な初期形にしない（連続性のため微小な残差を持たせる）。

## 全編構成案（20 秒 / 4 幕）

| 時間 | 幕 | 内容 | 音楽との対応 |
|---|---|---|---|

| 4–7s | フック余韻→接続 | 再結集した字形を保持しつつカメラ的な寄り or 筆画の1本を抜き出して「これは一つのシェイプ」と示す | BGM 4–7s（セクションA終端へ向かう） |

## 楽曲データ

`tools/analyze-music.ts`（新規・TypeScript）で mp3 をデコードし
スペクトルフラックス onset + テンポ推定を実施。成果物
`video/src/music-analysis.json`。

- duration 73.2s（PV は先頭 20s を使用、master comp と同じ）
- 推定テンポ ~215 BPM（16分音符グリッド相当）。拍グリッド
  `beatsSec` は約 0.279s 間隔、フレーズアクセントは 2 拍ごと（~0.558s）
- セクション境界（RMS 変化）: 0 / 7.0 / 14.5 / 22.0 … → 使用区間内は
  **7.0s と 14.5s の 2 箇所**が構造変化点。上表の幕転換と一致させた
- 強オンセットは 0–4s で約 0.07s 間隔の密なグリッド。全動作の
  拍同期はせず、場面転換・爆発・CTA 着地など主要変化にのみ使う

## 実収録素材の扱い

`verification/wu-d-live/wu-d-live-capture.mp4`（2.93s / WGC・on-change
フレーム）を第三者批評で確認した事実:

- 字形「筆」→ 制御点表示 → タイムラインのパラメータ展開 → 字形復帰、
  という Decompose 前後の状態変化は映っている
- 実行トリガー（Decompose ボタン/ダイアログ）は画角に無く、
  「実行した」ことは映像単体では立証できない（実行自体は
  `decompose-log.txt` の `items=13 created=13` が証拠）
- 解像度・UI 文字の判読性は限定的。使用時は ROI を字形/タイムラインの
  意味ある領域に絞り、拡大とカットで読ませる。デバッグ痕跡
  （カーソル・不要パネル）は除去する

方針: 「操作の瞬間」を演出で補わず、「入力（連結輪郭）→ Restro 処理 →
独立シェイプ群の出力」という因果を、実収録の前後状態 + 実処理ログの
事実に基づいて構成する。必要なら同経路での再収録を検討するが、
現行素材で成立する範囲を先に試す。
